# CR-0004: Multi-Channel Order Ingestion, Real-Time Order Tracking & Storefront Sync

| Dokumen | CR-0004 |
|---|---|
| Status | Terbuka / Dalam Rencana |
| Tanggal | 2026-10-30 |
| Terkait | BUG-0001 (WhatsApp checkout), BUG-0010, T10-T12 |
| Scope | API Backend (`api-happyBouquet`), Panel Admin (`PanelHappyBouquet`), Storefront (`happybouquet`) |

---

## 1. Konteks & Latar Belakang
HappyBouquet mengandalkan strategi omni-channel untuk penjualan buket bunga:
1. Pelanggan menyukai fleksibilitas pemesanan: direct WhatsApp, marketplace (Shopee / TikTok Shop), dan order langsung melalui website.
2. Saat ini, checkout web hanya mengarahkan ke link `wa.me` tanpa menyimpan pesanan ke database API. Akibatnya, pemilik toko harus menginput pesanan satu per satu secara manual ke Panel Admin.
3. Halaman pelacakan pesanan (`/tracking`) di storefront masih menggunakan mock data lokal Pinia (`userStore.orders`), sehingga tidak dapat melacak pesanan riil yang dibuat pelanggan atau diproses admin.
4. Halaman promo (`/promo`) masih memuat data statis/hardcoded yang tidak tersinkronisasi dengan master promo di API/Panel.
5. Kunjungan storefront belum mengirimkan data analitik ke endpoint internal API (`POST /api/analytics/collect`), menyebabkan dashboard analitik di Panel Admin kosong.

---

## 2. Solusi Desain Arsitektur (Ponytail - Ringkas & Efektif)

### A. Multi-Channel Order Ingestion
* **Order via Web (Web Ingestion)**:
  1. Pelanggan melengkapi data pengiriman dan opsi pembayaran di `pages/checkout/index.vue`.
  2. Saat tombol diklik, FE memanggil endpoint publik baru: `POST /api/orders/public`.
  3. API membuat record order di DB dengan `channel = 'Web'`, nomor pesanan otomatis (misal `HB-261030-XXXX`), dan status awal `pending_payment` / `waiting_confirmation`.
  4. Response mengembalikan `order_number`.
  5. FE langsung membuka WhatsApp penjual dengan template chat terisi nomor pesanan resmi, sekaligus menampilkan struk order di web dengan tautan langsung ke halaman pelacakan.
  6. **Hasil**: Pelanggan tetap menikmati kemudahan chat konfirmasi WhatsApp, sementara data order 100% otomatis tersimpan di Panel Admin.

* **Direct WhatsApp, Shopee & TikTok Channel**:
  1. Pada halaman detail produk (`/products/[slug]`), sediakan pill/tombol kanal alternatif selain "Beli Sekarang":
     * Tombol "Chat Admin WhatsApp" (membuka chat spesifik untuk konsultasi produk).
     * Tombol "Beli di Shopee" (jika link Shopee produk tersedia).
     * Tombol "Beli di TikTok Shop" (jika link TikTok produk tersedia).
  2. Setiap klik kanal eksternal memicu event telemetri ke `POST /api/analytics/collect` (event: `channel_outbound`, payload: `{ channel, product_id }`) sebelum membuka tab baru.

### B. Optimal Real-Time Order Tracking
* **API Backend**:
  1. Buat endpoint publik dengan perlindungan rate-limiter: `GET /api/orders/track/:orderNumber`.
  2. Sanitasi data: hanya kirim field yang aman untuk publik (nomor order, tanggal pesan, status alur [Menunggu Pembayaran -> Dikonfirmasi -> Dirangkai -> Siap Dikirim -> Dalam Pengiriman -> Selesai], inisial/nama penerima disamarkan, ringkasan nama item, ekspedisi & nomor resi jika ada). Data sensitif seperti modal (HPP/COGS) dan margin keuntungan tidak boleh keluar.
* **FE Storefront**:
  1. Halaman `pages/tracking.vue` membaca query URL (`?order=...`) atau input form pencarian.
  2. Panggil API `GET /api/orders/track/:orderNumber`.
  3. Render stepper timeline dinamis sesuai status riil pesanan di Panel.
  4. Jika pesanan tidak ditemukan, sediakan tombol bantuan langsung ke WhatsApp dengan teks: *"Halo admin, saya ingin menanyakan status pesanan nomor [NO_ORDER]"*.

### C. Sinkronisasi Promo & Analitik (Quick Wins)
* **Sync Promo**: `pages/promo.vue` memanggil `${apiUrl}/promos?active=true` secara reaktif dan menampilkan daftar kode promo aktif dari database.
* **Sync Analitik**: Plugin FE mengirim beacon page view ke `POST /api/analytics/collect` pada setiap perpindahan halaman (`page:finish`).
